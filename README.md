# 산불 대응 AI — 결과물 중심 목업 (2025-03-22 의성 산불, 발생 후 8시간)

캡스톤 「산불 확산 예측 기반 대응 의사결정 지원 시스템」의 핵심 기능(로그인·대시보드·확산 예측/렌더링·대응 제안·챗봇 QnA)이 **어떤 결과물로 보이는지**만 확인하기 위한 정적 목업입니다. 실제 예측 모델(ELMFIRE), RAG·LLM(EXAONE), 기상 API, 서버는 없습니다. 판단 규칙과 제안 문장은 `app.js` 안의 규칙·템플릿이고, 챗봇은 키워드 대본입니다.

## 열어 보기

- 로컬: `index.html`을 더블클릭하면 열립니다. 지도 타일·지형은 인터넷에서 받으므로 온라인이어야 합니다. 5개 파일(`index.html`, `app.js`, `data.js`, `data_boundaries.js`, `data_osm_lines.js`)은 같은 폴더에 있어야 합니다.
- GitHub Pages: 이 폴더를 저장소로 올리고 Settings → Pages → Branch `main` / root 로 켜면 `https://<계정>.github.io/<저장소>/` 에서 열립니다. `.nojekyll`이 있어 그대로 서빙됩니다.
- 로그인 화면에서 역할을 고릅니다. **의사결정권자**(의성군수)는 모든 기능, **열람자**는 읽기 전용입니다. 아이디·비밀번호는 아무 값이나 됩니다.

## 데모 순서(핵심 파일 UC 기준)

1. 로그인(UC-01) → 관할 상황판(UC-02): 왼쪽 탭 개요·기상·위험구역·자원·대피·타임라인
2. 「예측 실행」(UC-04) → P1~P8 생성 → 제안서 자동 생성(UC-08). 헤더에 규칙 판정 단계와 격상 검토 배너
3. 재생 ▶ / 슬라이더 / 속도(UC-05), 레이어 체크박스, 「3D 지형」
4. 「조건 변경」으로 풍속·풍향 what-if(UC-07). 기본 예측·제안서는 유지되고 흰 선으로 겹쳐 비교
5. 오른쪽 제안서: 진화 S1~S7 / 대피 E1~E7 카드, 구분 필터, 근거 [k] 클릭(UC-10), 「지도에서 보기」(UC-11), 채택·보류·수정 지시(UC-12, 브라우저에 저장)
6. 「질문」 → 챗봇(UC-13). 예: “왜 박곡리가 먼저입니까”, “헬기를 몇 대 더 투입해야 합니까”(근거 부족 응답)
7. 챗봇에 “박곡리 대피 완료” → 정정 확인 대화상자(UC-14) → 제안서 재생성 → 전후 비교
8. 「현장 보고 입력」(UC-03)으로 자원·진화율·대피 상태를 바꾸면 제안서가 다시 생성됩니다

## 시나리오와 데이터

- 기준시각 t0 = 2025-03-22 12:00(발생 11:25 후 36분). 공식 대응단계는 **2026년 개편 체계**(초기대응·확산대응 1·2단계)로 표시합니다. 2025년 당시는 구 1·2·3단계였습니다.
- 화선 P1~P8은 **합성 타원 모델**입니다(발화점·풍향·풍속). 실측 화선이 아닙니다.
- 화면의 <span>「실제」</span>/「가상」 표시와 상단 「출처」 버튼에 항목별 구분이 있습니다.

| 항목 | 구분 | 출처 |
|---|---|---|
| 발화점·시각·원인·실제 경과 | 실제 | 산림청 X, 위키백과, 이데일리 |
| 마을·면사무소·학교·사찰·복지시설 좌표 | 실제 | OpenStreetMap(Overpass) |
| 도로·철도 선형 | 실제 | OpenStreetMap |
| 읍면·군 경계, 읍면 인구 통계 | 실제 | 국가데이터처 SGIS |
| 화선 P1~P8 | 합성 | 타원 모델 |
| 마을별 인구·가구·고령·장애, 주택 점 | 가상 | 읍면 통계 참고 배분 |
| 기상 시계열·습도·시정, 특보 종류 | 가상 | 발생 시 풍속 5.6 m/s만 보도값 |
| 대피소 수용 인원, 요양병원 위치, 송전선, 대피로·진입로, 12:00 자원 | 가상 | 구하지 못한 항목 |
| 근거 텍스트 | 요약 | 표준매뉴얼 쪽수 기준 요약(원문 비공개) |

## 파일

| 파일 | 내용 |
|---|---|
| `index.html` | 화면 구조와 스타일 |
| `app.js` | 지도(MapLibre GL JS), 합성 확산 모델, 규칙 판정, 제안서 14블록 템플릿, 근거 드로어, 챗봇 대본, 정정 흐름, 채택 기록 |
| `data.js` | 시나리오 데이터(발화점, 마을, 시설, 대피소, 기상, 자원, 실제 경과, 근거 요약, 카탈로그) — 값을 바꾸려면 여기만 고치면 됩니다 |
| `data_boundaries.js` | 의성군·읍면 경계 GeoJSON(SGIS, WGS84 단순화) |
| `data_osm_lines.js` | 도로·철도 GeoJSON(OSM) |

외부 라이브러리: MapLibre GL JS 4.7(jsdelivr CDN). 지도 타일 © OpenStreetMap contributors, 지형 AWS Terrain Tiles.

## 수정 팁

- 마을을 추가·삭제하거나 인구를 바꾸려면 `data.js`의 `villages`를 고칩니다. 도달 슬라이스·대피 순서·대피소 배정은 자동으로 다시 계산됩니다.
- 확산 속도는 `data.js`의 `fire_model`(km/h = a + b × 풍속)로 조정합니다.
- 제안 문장 템플릿은 `app.js`의 `buildProposal()`에 S1~E7 순서로 있습니다.
- 챗봇 응답은 `app.js`의 `answer()` 표와 `detectCorrection()`에 있습니다.
